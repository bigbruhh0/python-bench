# Pneumatic Clamp Simulator

Программа симулирует зажатие и разжатие пневмоцилиндра. Вместо LinuxCNC используется `MemoryHAL` — имитация HAL-сигналов в памяти. Динамическая панель PyQt5 показывает входы, выходы, состояние автомата, таймер операции и журнал. Реального оборудования в проекте нет.

## Стек и слои

- Python 3.10+; PyQt5 для интерфейса; SQLite из стандартной библиотеки для настроек.
- `bench_sim/hal.py` — контракт HAL и его реализация `MemoryHAL`.
- `bench_sim/logic/controller.py` — конечный автомат и логика таймаутов.
- `bench_sim/data/settings.py` — SQLite-репозиторий и проверка настроек.
- `bench_sim/ui/gui.py` — динамическая панель симулятора.
- `bench_sim/ui/cli.py` — альтернативная интерактивная консоль.
- `bench_sim/__main__.py` — точка запуска, собирающая слои приложения.
- `tests/` — тесты состояний, выходов, таймаутов, настроек и интерфейса.

## Обоснование решений

`MemoryHAL` выбран вместо LinuxCNC, чтобы запускать и проверять логику без станка и его оборудования. Контроллер зависит от общего интерфейса HAL, поэтому имитацию можно заменить адаптером к реальному HAL. Таймер использует монотонные часы, чтобы перевод системного времени не влиял на таймауты, а в тестах время можно было продвигать без ожидания.

## Установка и запуск на Windows

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m bench_sim
```

По умолчанию запускается графический интерфейс. Датчики на панели переключаются вручную, команды зажатия/разжатия запускают соответствующую операцию. Таймауты можно менять и сохранять в SQLite. Для запуска консольного интерфейса используйте `python -m bench_sim --cli`.

При первом запуске создаются `settings.sqlite3` с параметрами по умолчанию и `bench.log` с журналом всех переходов состояний и ошибок. По умолчанию `T_clamp = 5` секунд, `T_unclamp = 2` секунды. Автоподтверждение включено: симулятор включает датчик зажатия через 1 секунду и датчик разжатия через 0,5 секунды. Если задержка подтверждения больше таймаута, операция завершается ошибкой. Коды ошибок `E001`, `E002` и конфликта `E003` хранятся в SQLite.

Отключите кнопку «Подтверждать автоматически», чтобы переключать датчики вручную. Кнопка «Посмотреть полные логи» открывает журнал `bench.log`, включая записи предыдущих запусков; кнопка «Обновить» перечитывает файл.

## Команды симулятора

- `clamp` / `unclamp` — подать команду зажать или разжать.
- `sensor clamped on|off` / `sensor unclamped on|off` — вручную изменить состояние датчика.
- `wait SECONDS` — подождать и проверить таймаут.
- `status` — показать состояние, выходы и код ошибки.
- `reset` — сбросить ошибку после устранения конфликта датчиков.
- `help` / `quit` — справка / выход.

Переход считается успешным, когда включается соответствующий датчик. При таймауте контроллер выключает оба выхода и выставляет `E001` или `E002`. Одновременные команды или одновременное срабатывание двух датчиков дают `E003`; ошибка остаётся до ручного сброса.

## Тесты

```powershell
pytest
```

Таймер контроллера получает монотонные часы через зависимость, поэтому тесты проверяют таймауты без реального ожидания.
